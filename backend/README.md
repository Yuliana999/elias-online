# Еліас — бекенд (крок 4: синхронна гра)

Авторизація й лобі готові, і тепер до них додано саму гру: сервер —
єдине джерело правди для рахунку/таймера/поточного слова, а не кожен
пристрій окремо.

Стек: **Node.js + Express + MongoDB (Mongoose) + Socket.io + JWT**.

## Що вже є

- Підключення до MongoDB Atlas
- Модель `User` з `publicId` у тому ж форматі, що вже використовує фронтенд
  (напр. `F7K2QW`) — саме ним гравці будуть ділитись, щоб приєднатись до лобі
- Реєстрація / вхід / refresh / logout / `GET /api/auth/me`
  - паролі хешуються через bcrypt
  - access-токен (JWT, коротка дія) повертається в тілі відповіді
  - refresh-токен (довга дія) лежить у httpOnly-кукі
- **Лобі**: створення за кодом, приєднання гравців, розподіл по командах,
  старт гри — `POST /api/lobby`, `GET /api/lobby/:code`,
  `POST /api/lobby/:code/join`, `POST /api/lobby/:code/team`,
  `POST /api/lobby/:code/start`
- Socket.io: підключення перевіряє access-токен і вміє тримати гравця в
  кімнаті лобі (`lobby:join` / `lobby:leave` з клієнта), куди контролер
  лобі шле `lobby:update` і `lobby:started`
- **Гра** (`src/game/`): при старті лобі сервер створює авторитетний стан
  гри (`engine.js` — команди з `playerIds`, перемішаний банк слів, рахунок,
  раунди) і тримає його в пам'яті процесу (`store.js`, мапа `код → стан`).
  Клієнти керують ним подіями:
  - `game:startTimer` — запускає серверний `setInterval`, який щосекунди
    шле всім `game:tick { timeLeft, running }`
  - `game:guess { correct }` — команда вгадала/скіпнула слово, сервер
    рухає `wordIdx`/рахунок і розсилає `game:state`
  - `game:endTurn` — передає хід наступній команді (або, якщо раунди
    вичерпані, шле `game:finished` і прибирає гру зі стору)

  Кожна дія перевіряє `socket.userId` проти `playerIds` команди, чий зараз
  хід — гравці іншої команди чи глядачі нічого змінити не можуть.
- `GET /health` для перевірки, що сервер живий

## Крок 3: обробка помилок і валідація

- `utils/asyncHandler.js` — обгортка над кожним async-роутом, яка ловить
  reject і передає в `next(err)`, щоб такі помилки більше не вішали запит
  без відповіді (проблема Express 4 з голими async-хендлерами)
- Загальний error-мідлвар у `server.js` тепер розрізняє помилки Mongoose
  (`ValidationError` → 400, дублікат ключа `code 11000` → 409) від
  справжніх 500-х
- `middleware/validate.js` + `validators/*.validators.js` — вхідні дані
  `POST /api/auth/register`, `/login` та `POST /api/lobby`,
  `/:code/team` тепер валідуються через **zod** ще до контролера
  (мінімальна довжина пароля, формат `mode`/`team` тощо), а не
  вручну через `if`

## Чого ще немає (наступні кроки)

1. **Результати та історія ігор**: збереження завершених партій у Mongo,
   ендпоінт історії користувача
2. Стан гри живе лише в пам'яті процесу — рестарт сервера під час партії
   її зітре; для одного інстансу на Render/Railway це ок, але не переживе
   деплой просто посеред гри
3. Деплой бекенда й фронтенда, щоб грати з різних мереж, а не лише в
   одному Wi-Fi

## Запуск

```bash
npm install
cp .env.example .env   # і встав туди свій MONGODB_URI + секрети
npm run dev
```

Сервер підніметься на `http://localhost:4000` (або порту з `.env`).

## Структура

```
src/
├── server.js              # точка входу: express + http + socket.io
├── config/db.js           # підключення до MongoDB
├── models/User.js, Lobby.js
├── routes/, controllers/, validators/  # auth + lobby REST
├── middleware/auth.middleware.js, rateLimit.js, validate.js
├── data/wordBanks.js      # копія словника фронтенду — сервер сам обирає слова
├── game/
│   ├── engine.js           # чиста логіка: команди, слова, стан гри
│   └── store.js            # мапа код лобі → стан гри в пам'яті
├── sockets/index.js        # lobby:* + game:* realtime-події
└── utils/
    ├── id.js               # генерація publicId у форматі фронтенду
    └── tokens.js           # підпис/перевірка JWT
```

## Ендпоінти

| Метод | Шлях               | Опис                                  | Авторизація |
|-------|--------------------|----------------------------------------|-------------|
| POST  | `/api/auth/register` | `{ name, password }` → акаунт + токен | ні |
| POST  | `/api/auth/login`    | `{ publicId, password }` → токен      | ні |
| POST  | `/api/auth/refresh`  | оновити access-токен за кукі          | refresh-кукі |
| POST  | `/api/auth/logout`   | інвалідувати сесію                    | refresh-кукі |
| GET   | `/api/auth/me`       | дані поточного користувача            | Bearer access-токен |

# Еліас Online

Монорепо: фронтенд (React + Vite) і бекенд (Node.js + Express + MongoDB +
Socket.io) в одному проєкті.

```
elias-online/
├── frontend/     # React-додаток (поки на моках, див. frontend/README.md)
└── backend/      # Express API + Socket.io (поки лише авторизація, див. backend/README.md)
```

## Швидкий старт

```bash
npm run install:all   # ставить залежності і в frontend/, і в backend/
cp backend/.env.example backend/.env   # і встав свій MONGODB_URI + секрети
npm run dev            # піднімає фронтенд (5173) і бекенд (4000) одночасно
```

Або окремо:

```bash
npm run dev:frontend
npm run dev:backend
```

## Стан інтеграції

Фронтенд і бекенд **з'єднані**:

- Реєстрація/вхід/вихід ідуть через `/api/auth/*` (JWT access-токен у
  пам'яті + httpOnly refresh-кукі, автовідновлення сесії при перезавантаженні
  сторінки).
- Лобі (парна й командна гра) створюється й приєднується через `/api/lobby/*`
  і синхронізується в реальному часі через Socket.io (`lobby:update`,
  `lobby:started`) — усі учасники бачать склад команд і налаштування
  (тривалість раунду, жанр слів) одночасно.
- **Гра тепер теж синхронна й веде її сервер** (не клієнт): при старті лобі
  бекенд сам будує команди/порядок слів і рахує таймер, а клієнти лише
  малюють стан і шлють дії (`game:startTimer`, `game:guess`, `game:endTurn`),
  тож усі учасники — з різних телефонів і комп'ютерів — бачать однаковий
  рахунок, слово й час одночасно. Кнопки активні лише на пристрої гравця
  тієї команди, чий зараз хід.
- Одиночна гра (`solo`) як і раніше повністю локальна — лобі й бекенд їй
  не потрібні.

По дорозі також виправлено баг у бекенді: `lobby.controller.js` імпортував
неіснуючу `genUniqueLobbyCode` з `utils/id.js` — сервер падав ще на етапі
імпорту модулів, до будь-якого запиту. Функцію додано.

## Нещодавно доробили

- **Кик гравця з лобі** — капітан бачить кнопку "✕" біля кожного гравця
  (крім себе) на екрані лобі, доки гра не почалась. Кикнутому летить
  окрема подія (`lobby:kicked`), яка одразу виводить його на меню з
  поясненням.
- **Ліміт на розмір лобі в командному/кастомному режимі** —
  `MAX_TEAM_LOBBY_SIZE = 8` (`backend/src/config/constants.js`), окремо
  від ліміту на команду (`MAX_TEAM_SIZE = 2`). Раніше нічого не заважало
  лобі розпухати гравцями "без команди".
- **Відновлення пароля** — необов'язковий email при реєстрації,
  `POST /api/auth/forgot-password` + `POST /api/auth/reset-password`
  (токен на 1 годину, у базі лежить лише його sha256-хеш). Якщо в `.env`
  бекенда не задані `SMTP_*` — лист просто друкується в консоль сервера
  (зручно для розробки); постав `SMTP_HOST/SMTP_USER/SMTP_PASS` (напр.
  Gmail app password) — і листи підуть насправді. На фронтенді — форма
  "Забув(ла) пароль?" на екрані входу та екран `ResetPassword.jsx` за
  посиланням з листа (`?resetToken=...`).
- **Партія переживає рестарт сервера** — стан активної гри, як і раніше,
  живе в пам'яті процесу заради швидкості (`backend/src/game/store.js`),
  але тепер кожна суттєва зміна (старт, вгадане/скіпнуте слово, кінець
  ходу) додатково асинхронно зберігається "знімком" у Mongo
  (`GameState`). Якщо процес впаде посеред гри — при наступному старті
  сервер підхоплює ці знімки назад: рахунок і прогрес по словах не
  губляться. Таймер після рестарту завжди зупинений (`setInterval` не
  серіалізується) — гравцям доведеться самим натиснути "старт" ще раз.

## Встановлення на новій машині

Якщо `npm run dev` лається на нативні біндинги (`rollup`/`esbuild` —
типово після перенесення `node_modules` між Windows/Mac/Linux), видали
`node_modules` у `frontend/`, `backend/` і в корені та постав заново:

```bash
rm -rf node_modules frontend/node_modules backend/node_modules
npm run install:all
```
